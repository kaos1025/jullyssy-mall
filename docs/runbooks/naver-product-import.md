# 네이버 스마트스토어 상품 임포트 절차서

> 대상: 운영자 / 작성 근거: US-4 (상품 확충)
> 핵심 목적: **네이버 스마트스토어 상품을 자사몰로 가져와 카탈로그를 확충한다.**

---

## 0. 개요 — 왜 지금 해야 하는가

자사몰은 현재 스마트스토어 전체 645개 상품 중 **60개(약 9%)** 만 임포트된 상태이며, 자사몰 자체 상품은 0개다. 자사몰 중심 전환의 1단계는 상품 카탈로그를 충분히 갖추는 것이며, 임포트는 이미 구현된 기능이다(코드 신규 작업 없음). 본 절차서는 운영 작업으로서 상품을 일괄 가져오는 전 과정을 안내한다.

### 코드 측 준비 상태 (운영자 액션 불필요)

| 자산 | 파일 | 상태 |
|---|---|---|
| 임포트 API | `src/app/api/naver/import/route.ts` | ✅ 1회 최대 500개 처리 |
| 임포트 UI | `src/components/layout/NaverImportButton.tsx` | ✅ 어드민 상품 관리 페이지에 노출 |

| 동기화 cron | 마이그레이션 053 | ✅ 매시간 재고/품절/상태 동기화 |

- 하단에 선택 수가 반영됨.

### 5단계 — 가져오기 실행

다이얼로그 우측 하단 **"선택한 N개 임포트"** 버튼 클릭.

처리 중에는 버튼이 "임포트 중..."으로 바뀐다. 완료되면 토스트 알림이 나타난다:

```
임포트 완료 — 총 N건 중 성공 M건, 실패 K건
```

임포트 완료 후 다이얼로그는 자동으로 현재 검색 결과를 새로고침하며, 이미 임포트된 상품이 "제외됨" 카운트에 반영된다.

**합격 기준**
- 토스트 알림에 성공 건수가 1 이상.
- 실패 건수가 0 (또는 실패 원인 확인 후 재시도).

## 2. 임포트 시 자동 처리 내역

임포트 버튼을 누르면 서버측(`/api/naver/import`)에서 상품별로 아래 처리가 자동 수행된다. 별도 설정 불필요.

| 처리 항목 | 설명 |
|---|---|
| **중복 skip** | `naver_product_no` 기준으로 이미 임포트된 상품(DELETED 제외)은 자동 skip |
| **fit_type 4-Layer 추론** | 의류 상품에 한해: ① 네이버 productAttributes+카테고리 사전 → ② sellerTags 키워드 → ③ 상세설명 휴리스틱 → ④ REGULAR 기본값 |
| **비의류 fit_type NULL** | 가방·신발·악세서리 등 비의류 카테고리는 fit_type을 NULL로 저장 |
| **카테고리 매핑** | `naver_category_mappings` 테이블 조회 → 매핑 없으면 네이버 카테고리 API 조회 후 자동 추가 |
| **이미지 등록** | 대표 이미지(is_thumbnail=true) + 추가 이미지 순서대로 `product_images` 저장 |
| **옵션 등록** | 옵션 조합(색상/사이즈/재고) → `product_options` 저장. 옵션 없는 상품은 기본 옵션(색상 "기본", 사이즈 "FREE") 자동 생성 |
| **상태 변환** | 스토어 SALE → 자사몰 ACTIVE, 그 외 → HIDDEN |
| **SEO 생성 큐 등록** | `seo_generation_queue`에 `trigger_source=naver_import`로 자동 enqueue (실패해도 임포트 성공으로 처리) |
| **동기화 로그 기록** | `naver_sync_logs`에 `sync_type=IMPORT`, 성공/실패/부분 상태 기록 |
| **목록 캐시 무효화** | 성공 건수 > 0 이면 `revalidateTag("products")` 자동 실행 |

## 3. 임포트 ↔ 동기화 관계 (중요)

임포트와 자동 동기화는 역할이 다르다. 혼동하지 않도록 한다.

| 구분 | 임포트 | naver-sync cron |
|---|---|---|
| **목적** | 신규 상품 1회 스냅샷 | 기존 임포트 상품의 재고·품절·상태 동기화 |
| **트리거** | 운영자 수동 실행 | 마이그레이션 053, 매시간 자동 실행 |
| **이미 있는 상품** | skip (업데이트 안 함) | 재고/품절만 반영(품절→재고0, 스토어 삭제→HIDDEN). 가격·ACTIVE 복원은 안 함 |
| **가격** | 임포트 시 1회 스냅샷 저장 | **동기화 안 함** (자사몰 독자 관리) |
| **오버셀 방지** | 해당 없음 | cron이 실시간 재고 반영 → 오버셀 차단 |

> **핵심**: 임포트 후 가격·이미지 갱신이 필요하면 자사몰 어드민에서 직접 편집해야 한다. 재임포트는 이미 있는 상품을 업데이트하지 않는다(의도적 설계 — 자사몰 독자 관리 보장).

## 4. 645개 전체 확충 배치 계획

1회 최대 500개 제약으로 인해 전체 확충은 최소 2배치로 나눈다.

| 배치 | 대상 | 예상 소요 |
|---|---|---|
| 배치 1 | 전체 조회 후 최대 500개 선택 → 임포트 | 수분 (상품당 상세 조회 1회 API 호출) |
| 배치 2 | 배치 1 완료 후 재조회 → 남은 145개 선택 → 임포트 | 수분 |

> **주의**: 500개 임포트는 네이버 커머스 API 상세 조회를 500회 호출한다. 네이버 API 호출 한도가 우려되면 100~200개 단위 소배치로 나눠 진행한다.

```sql
SELECT sync_type, status, total_count, success_count, fail_count, created_at
FROM naver_sync_logs
WHERE sync_type = 'IMPORT'
ORDER BY created_at DESC
LIMIT 5;
```

### 5-B. SEO 생성 큐 처리

임포트된 신규 상품은 모두 `seo_generation_queue`에 enqueue된다. SEO worker가 meta_description·search_tags를 자동 생성하며, 생성 후 검수가 필요하다.

```
어드민 → SEO 초안 관리 (또는 /admin/seo-drafts)
→ 신규 상품 초안 검수 (승인 / 수정 후 승인)
```

검수가 쌓이면 SEO 노출률이 낮아지므로 임포트 직후 일괄 검수를 권장한다.

### 5-C. 카테고리 매핑 확인

어드민 → 상품 관리 → 필터: 카테고리 미지정

### 5-D. 동기화 cron 활성화 확인

임포트된 상품의 재고는 naver-sync cron(마이그레이션 053)이 매시간 동기화한다. cron이 비활성화돼 있으면 오버셀이 발생할 수 있다.

```sql
-- 마지막 동기화 로그 확인
SELECT sync_type, status, total_count, success_count, created_at
FROM naver_sync_logs
WHERE sync_type = 'STOCK_SYNC'
ORDER BY created_at DESC
LIMIT 3;
```

최근 1~2시간 이내 STOCK_SYNC 로그가 있으면 cron이 정상 동작 중이다.

## 6. 주의사항

| 항목 | 내용 |
|---|---|
| 재임포트는 업데이트 아님 | 이미 임포트된 상품(DELETED 제외)은 재임포트 시 skip. 가격·이미지 갱신은 자사몰 어드민에서 직접 편집 |
| 가격은 자사몰 독자 관리 | cron 동기화가 가격을 덮어쓰지 않음. 스마트스토어 가격이 바뀌어도 자사몰 가격은 유지됨 |
| 대량 임포트 시 API 부하 | 500개 = 네이버 API 상세 조회 최대 500콜. 불안하면 100~200개 단위로 분할 |
| 판매 중지 상품 처리 | 스토어에서 STOP_SALE인 상품은 자사몰 HIDDEN으로 임포트됨. 직접 ACTIVE로 변경 가능 |
| DELETED 상품 재임포트 | 자사몰에서 DELETED 처리된 상품은 중복 skip 제외 대상 → 재임포트 가능 |

| 증상 | 원인 | 조치 |
|---|---|---|
| 임포트 토스트에 실패 N건 | 상품번호 미조회·상세 조회 실패 | `naver_sync_logs`의 `error_details` 확인 후 해당 상품번호만 재선택 임포트 |

| 500개 초과 선택 시 오류 | API 하드 제한 | 500개 이하로 분할 후 재시도 |

- **가격 일괄 조정**: 자사몰 가격은 임포트 후 수동 편집 또는 별도 일괄 변경 도구 필요.
